Understanding Error Plots
=========================

This page provides a detailed guide on how to read and interpret the logical error plots
generated by TQEC. These plots are a central tool for analyzing the performance of
surface code computations under various noise conditions.

Overview of the Plot
--------------------

The error plot displays the relationship between physical error rates and logical error
rates for a given quantum computation. It consists of:

1. **Main plot (top-right)**: Log-log plot showing logical error rate vs physical error rate
2. **Inset plot (bottom-left)**: ZX-graph visualization of the quantum circuit with
   highlighted edges indicating the computation and observable being measured

.. figure:: ./media/error_plot_overview.png
   :alt: Example error plot with ZX-graph inset

   Example error plot showing logical error rates for different code distances (d=3, 5, 7)
   with the corresponding ZX-graph visualization in the inset.

Reading the Axes
----------------

**X-axis: Physical Error Rate (p)**
   The probability of a single-qubit error occurring during each error correction cycle.
   This is typically parameterized as uniform depolarizing noise, meaning each qubit
   has an independent probability :math:`p` of experiencing an error.

**Y-axis: Logical Error Rate (per shot)**
   The probability that the computation produces an incorrect logical outcome after
   syndrome extraction and decoding. A "shot" refers to a single execution of the
   quantum circuit, including initialization, syndrome extraction rounds, and measurement.

Understanding the Curves
-----------------------

Each curve in the plot corresponds to a different **code distance** :math:`d`.

**Code Distance (d)**
   The distance of the surface code determines how many physical errors are required
   to cause a logical error. Higher distances provide better error correction but
   require more physical qubits and longer syndrome extraction times.

**Below-Threshold Region (left side of plot)**
   When the physical error rate :math:`p` is below the threshold :math:`p_\text{th}`,
   the code is operating in its error-correcting regime. In this region:

   - Increasing the code distance :math:`d` reduces the logical error rate
   - The curves for different distances are well-separated
   - The logical error rate scales as :math:`p_\text{logical} \propto p^{(d+1)/2}`

**Above-Threshold Region (right side of plot)**
   When :math:`p > p_\text{threshold}`, errors accumulate faster than they can be
   corrected. In this region:

   - Increasing :math:`d` may not improve or may even worsen performance
   - The curves for different distances converge or cross
   - The code no longer provides error correction benefit

The Threshold
------------

The **threshold** :math:`p_\text{th}` is the critical physical error rate at which
the error correction transition occurs. For the surface code under independent
 depolarizing noise:

- **Theoretical threshold**: approximately 1% (10⁻²)
- **Typical experimental values**: between 0.5% and 1.5% depending on noise model

**Locating the Threshold**
   The threshold can be approximately identified by finding where the curves for
   different distances intersect or come closest together. The inset plot in the
   upper-right corner (if present) shows a magnified view of this region with
   threshold fitting curves.

Below-Threshold Behavior and Error Suppression
---------------------------------------------

The most important feature to analyze is the **slope of the curves in the
below-threshold region**. This slope directly measures the **error suppression factor**
:math:`\Lambda`:

.. math::

   p_\text{logical} \approx \Lambda \cdot p^{d+1 \over 2}

**Understanding :math:`\Lambda`**
   The error suppression factor :math:`\Lambda` quantifies how effectively the code
   suppresses errors:

   - :math:`\Lambda \gg 1`: Strong error suppression (desirable)
   - :math:`\Lambda \approx 1`: Minimal improvement over physical error rate
   - :math:`\Lambda < 1`: Above-threshold behavior

**Why the Slope Matters**
   The exponential relationship means that for every order-of-magnitude improvement
   in physical error rate, the logical error rate improves by a factor of
   :math:`\Lambda^{(d+1)/2}`. A larger :math:`\Lambda` indicates that:

   1. The code is more effective at correcting errors
   2. Each additional round of error correction provides more benefit
   3. The system is operating well below its threshold

Pseudo-Threshold
---------------

The **pseudo-threshold** is the physical error rate at which a given code distance
:math:`d` achieves a logical error rate equal to the physical error rate
(:math:`p_\text{logical} = p`). This is distinct from the asymptotic threshold
which is defined in the limit of large :math:`d`.

**Practical Significance**
   - For :math:`p < p_\text{pseudo}`, the logical qubit outperforms a single
     physical qubit
   - The pseudo-threshold is always higher than the true threshold
   - At low distances, the pseudo-threshold can be significantly higher

ZX-Graph Inset
--------------

The inset plot (bottom-left corner) displays a **ZX-graph** representation of the
quantum computation:

**ZX-Calculus Basics**
   - **Green (Z) spiders**: Represent Z-type stabilizers or Z-basis measurements
   - **Red (X) spiders**: Represent X-type stabilizers or X-basis measurements
   - **Edges**: Represent qubit wires or entanglement between stabilizers
   - **Boundary colors**: Indicate the type of logical observable

**What the Inset Shows**
   The highlighted edges in the ZX-graph correspond to the specific observable
   being measured in the error rate experiment. This visualizes:

   1. The structure of the quantum circuit
   2. Which qubits participate in the logical operation
   3. The spatial and temporal extent of the computation

How Data Points are Computed
----------------------------

Each point in the plot represents a complete simulation pipeline:

1. **Circuit Generation**: A quantum circuit is generated for the computation
   with the given code distance :math:`d`

2. **Noise Injection**: The circuit is run with a specific physical error rate :math:`p`
   using the configured noise model (typically uniform depolarizing noise)

3. **Sampling**: The noisy circuit is executed many times (shots) to collect statistics

4. **Syndrome Extraction**: For each shot, the error syndromes are collected from
   the detector instructions in the Stim circuit

5. **Decoding**: The syndrome data is passed to a decoder (typically PyMatching)
   which predicts the logical outcome

6. **Comparison**: The predicted logical outcome is compared with the expected
   result to determine success or failure

7. **Logical Error Rate**: The proportion of shots with incorrect logical outcomes
   is computed as:

   .. math::

      p_\text{logical} = \frac{\text{Number of failed shots}}{\text{Total shots}}

Confidence Intervals
--------------------

Each data point includes **confidence intervals** (error bars) that indicate the
statistical uncertainty in the measured logical error rate.

**How Confidence Intervals are Computed**
   TQEC uses the **Wilson score interval** for binomial proportion confidence
   intervals, rather than the standard symmetric confidence interval. This method
   provides more accurate estimates, especially for:

   - Very low error rates (rare events)
   - Small sample sizes
   - Proportions near 0 or 1

**Why Confidence Intervals Vary**
   The size of confidence intervals depends on:

   - **Number of shots**: More shots → smaller intervals
   - **Number of failures**: Fewer failures → larger intervals
   - **Error rate**: Very low error rates need many shots to observe failures

**Large Intervals at Low Noise**
   At very low physical error rates (:math:`p < 10^{-4}`), you may observe:

   - Wider confidence intervals due to fewer observed failures
   - Missing data points for some distances (insufficient failures observed
     within the maximum shot budget)
   - Asymmetric error bars (characteristic of Wilson score intervals)

This behavior is expected and indicates that more simulation shots would be needed
to achieve the same statistical precision at lower error rates.

Common Plot Configurations
--------------------------

**Multiple Observables**
   Some computations measure multiple logical observables. In these cases, the plot
   may show separate subplots or different line styles for each observable.

**Distance Scaling**
   Standard plots show distances :math:`d = 3, 5, 7` (odd distances are used
   because the surface code requires odd distances to encode a logical qubit).

**Inset Threshold Plot**
   When using :func:`tqec.simulation.plotting.plot_threshold_as_inset`, an
   additional magnified view shows the threshold region with fitting curves.
